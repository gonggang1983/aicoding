# 第五轮：首版去除文件导出的范围收缩与复评

> 本轮仍属第 4 步。本文件记录最新范围决策与自复评；历史导出设计和探针结论不覆盖本记录。

## 1. 用户授权与需求变更

用户原话：“首版只返回 Markdown/JSON 报告，不提供报告文件导出；据此收缩 PRD 和设计，继续留在第 4 步复评，不进入第 5 步。”

这是移除首版功能，不是降低仍保留功能的安全承诺。需求唯一源为 [PRD](../02-prd/PRD.md)；仅修改相关条款，不把其他历史待确认细则一并标为用户已批准。

## 2. 最小产品闭环

指定 Node.js 项目 → 发现脚本/手工任务和 Git 摘要 → 预览计划 → 真实宿主批准 → 串行检查 → 同一结果返回 Markdown/JSON。

- 四个工具：discover、preview、run、report；无 export 工具，也不保留永远 unavailable 的导出占位。
- 必需：真实退出证据、超时/取消/unknown、有限输出和脱敏、同会话取报告、独立宿主装配。
- 排除：报告文件/暂存文件、报告写盘审批/回执、专用 Service、原生文件后端、导出能力探测和替代算法研究。
- 不增加自动修复、依赖安装、提交/推送/发布、远程适配、持久历史或后台服务。

## 4. 仍须保留的验证义务

- G-01：固定版本制品、类型及独立插件真实装配。不能用 import 成功代替宿主调用。
- G-02：Windows 中文/空格、npm 参数/生命周期转发、受管子进程超时/取消。
- G-04：真实审批展示、批准/拒绝、取消后报告可取；不以模型 approved 声明替代。
- G-05：有界输出、脱敏及报告一致性，不向宿主 spill 原始日志。

这些是保留功能必需的最小验证义务，不是额外平台建设，也未因去掉导出而通过。后续获批实施的首个切片优先证明“独立加载—发现—批准/拒绝执行—报告返回”；条件不足就停止并回报，不绕过宿主或自动安装。

## 6. 最新结论与暂停点

**收缩版设计自复评通过（仅设计层）。** 本轮未发现继续保留原导出 P0 的理由；当前最小闭环不依赖未成立的原生发布候选。审批、沙箱、脱敏、真实终态及宿主验证要求均保留。

本结论不等于实现完成、安全审计通过、平台兼容已证实或 AC 已验收；全部产品 AC 仍待实际执行证据。历史严格共享探针失败事实保持不变，未来恢复导出需重新批准范围并评审，不自动复活旧契约。
