## 3. 本轮优先发现：仍归属 R-01，不重复造问题编号

### 3.1 F-02：不共享删除不是完整的重解析防护

E-04 证明删除/重命名访问的共享互斥，E-07 则表明重解析点有按句柄修改操作。现有证据不足以断言两者完全互斥；也不能仅因拿到目录句柄就认为后续相对打开完全不受属性变化影响。

候选已明确这个反例，不将“deny delete”写成完整证明。必须核实 OBJ_DONT_REPARSE、单组件相对打开及已打开根目录的实际组合语义。若改成 deny write，需同时证明不会破坏正常发布，不可一边放宽共享一边仍声称 I1 成立。

### 3.2 F-03：句柄发布不是只换一个 API 名

Win32 FILE_RENAME_INFO 与 WDK FILE_RENAME_INFORMATION 不能混用结构布局。需要确定目标目录句柄、源 DELETE 权限、共享模式及 no-replace 竞争行为。文档支持研究方向，不证明特定二进制可运行。候选已排除路径临时目录与路径清理，避免只保护最终发布。

### 3.3 F-04：服务注册不等于权限继承

原生能力的政策判定、真实目录身份、fs/write-intent 监听器决定及 fs/observed 版本必须连成可审核契约。单独 resolve 一次或复制 containment 代码不够；allowed-once 不能覆盖 read-only。政策变更的生效点需和真实宿主对齐，不能编造宿主未提供的原子快照保证。
