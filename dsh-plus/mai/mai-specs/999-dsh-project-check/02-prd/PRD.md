## 1. 背景与目标（Why）

AI 修改代码后，开发者仍需逐项确认 Git 改动、测试和构建是否真正执行。口头“完成”不能替代执行证据。

- 已确认：独立安装的 DSH 插件；面向 Node.js 项目，手工配置任务、Git 摘要、经批准执行、Markdown/JSON 报告。
- 已确认：不自动修复、安装依赖、提交、推送或发布；不绕过宿主审批和沙箱，不将检查通过称为业务验收通过。
- 本地事实：当前工作区只有 AI 资产和规格，没有插件源码或产品界面；AGENTS 文件为空，不把其他作业视为插件实现。
- 外部事实：本轮读取官方工具教程及流水线文档，确认其描述工具注册、审批及结果处理扩展机制；尚未安装或运行 DSH，不能据此声称具体版本兼容。
- 拟议细则：npm 首发范围、Windows 首验范围、数值默认值和交互细则待人工确认；API、版本、源码路径留给技术设计。

**目标**：先发现而不执行；仅运行选定且批准的任务；保留真实证据和缺口；同一结果生成两种报告；在固定 DSH 版本真实验证安装、调用和拒绝审批。成功以第 9 节 AC 的实际证据衡量，不承诺未经测量的效率收益。

## 3. 总体业务流程

### BF-01：发现 → 预览 → 批准 → 执行 → 报告

用户在 DSH 会话触发体检，从指定项目开始，到获得报告或明确阻断原因结束。沿用宿主会话、工具结果和审批入口，不新增页面。

1. 校验路径，读取 package.json、手工配置、Git 状态；不执行项目脚本、安装或生命周期脚本。
2. 展示候选脚本、已配置任务、Git 摘要和缺失条件；发现不代表获得执行授权。
3. 用户选择配置任务；无有效配置时只返回发现报告，不自动生成配置后立即运行。
4. 展示项目路径、任务 ID、实际命令参数、目录、超时和任意代码风险。
5. 取得与计划绑定的宿主一次性批准；拒绝、取消、不可用或计划变化均不启动相应任务。
6. 按配置顺序串行执行；普通非零退出后继续其他已批准任务；整次取消停止调度；不自动重试。
7. 汇总脱敏结果，在会话中返回同一 run 的 Markdown/JSON；首版不提供报告文件导出或报告落盘操作。
8. 修正后重新预览批准，生成新 run，不改写旧结论。

### BF-02：异常与降级

非 Node.js、无任务、无 Git、命令缺失、审批拒绝和结果不可用分别呈现；保留可读事实，不换目录、不自动安装、不推断通过。

## 9. 验收标准（Acceptance Criteria）

下列为待批准的验收承诺，尚未执行；Given/When/Then 描述可判定场景，不是测试结果。

### AC-01：发现不执行

关联：FR-01、FR-02、BR-01。
- Given：含 test/build 和带可观察副作用脚本的 Node.js 样例。
- When：仅发起发现，含省略路径的场景。
- Then：返回正确路径和候选/配置区分；副作用标记不存在，没有项目脚本执行。
- 验证方式：合成项目自动测试；真实宿主发现调用复核。

### AC-02：无效项目和配置阻断

关联：FR-01、FR-02、FR-09、BR-02、BR-03、NFR-02/03。
- Given：分别构造路径不存在、非 Node.js、非法 JSON、无 scripts、重复 ID、脚本缺失、参数非数组、超时越界、超过 20 任务、文件超过 1 MiB、非 npm 或冲突包管理器。
- When：发现或请求执行。
- Then：定位错误；无有效任务或所选配置不合法时不启动脚本；零任务总览不是通过；不换目录、不自动安装、不回退包管理器。
- 验证方式：参数化边界与负例测试。

### AC-03：Git 摘要真实且限定范围

关联：FR-03、BR-01、BR-11、NFR-03。
- Given：样例仓库含 staged、unstaged、untracked、重命名和项目子树外修改。
- When：采集执行前后摘要；另测 clean、非仓库、Git 缺失和超过 200 项。
- Then：路径/状态正确且仅目标子树，无正文和 Git 索引修改；截断、省略量和不可用原因明确；不能将差异全部归因于任务。
- 验证方式：临时 Git 仓库集成测试，记录前后状态。

### AC-04：批准与计划绑定

关联：FR-04、FR-09、BR-04、BR-08、NFR-01。
- Given：有效任务及完整计划。
- When：依次测试批准、拒绝、审批不可用、伪造批准参数、批准后修改配置或 script。
- Then：只有与当前计划匹配的真实批准允许启动；其他情况不启动相应任务，原因可查；预览含路径/参数/超时及生命周期风险。
- 验证方式：自动化批准适配测试，加真实 DSH 批准/拒绝调用证据；模拟不能替代宿主验证。

### AC-05：退出结果与串行规则

关联：FR-05、FR-06、BR-05～BR-07、NFR-02。
- Given：按顺序配置退出码 0、退出码非零但打印 success、退出码 0 的三个脚本。
- When：批准运行。
- Then：串行且按序执行三项，状态 passed/failed/passed；记录真实退出码、非负耗时和起止；总览失败，无自动重试。全成功非空集合则检查通过。
- 验证方式：真实子进程样例和结果断言。

### AC-06：超时、取消和终止未知

关联：FR-05、FR-09、BR-05、BR-12、NFR-02。
- Given：超时脚本、带子进程脚本、排队任务及不能确认终止的适配样例。
- When：超时、用户取消或插件卸载。
- Then：停止调度；发起进程树终止；确认停止的运行任务 failed，排队未启动任务 not_run；5 秒内未确认退出则 unknown 并提示残留风险。不遗漏终态或错误判通过。
- 验证方式：真实进程超时/取消集成，加终止异常注入测试。

### AC-07：缺依赖与结果缺失

关联：FR-06、FR-09、BR-05、BR-06。
- Given：npm 不可用、脚本运行时依赖缺失、执行通道丢失终态的不同样例。
- When：发起执行。
- Then：未启动为 not_run；真实启动非零退出为 failed；可能启动但无终态为 unknown；总览分别证据不足/检查失败/证据不足，不自动安装依赖。
- 验证方式：环境隔离和故障注入测试。

### AC-08：总览和未选项不误导

关联：FR-06、FR-08、BR-06、COPY-03/04。
- Given：零选择、全通过、包含失败、通过加未执行、通过加未知，以及无 Git 的全通过集合。
- When：生成结论。
- Then：按 BR-06 优先级判定；未选项列为不覆盖；无 Git 的任务通过仍提示变更证据缺失；始终有非业务验收声明。
- 验证方式：状态组合表自动测试。

### AC-09：大输出、脱敏和不执行日志

关联：FR-05、FR-07、BR-09、NFR-03～NFR-05。
- Given：超过 64 KiB 的混合输出，含跨流分片凭据、用户敏感字面值、URL 凭据、控制字符和伪造操作指令。
- When：执行、渲染、返回/缓存报告和记录插件日志。
- Then：流持续消费不阻塞；保留量有界且标截断；受规则保护秘密不出现在两份报告、插件日志；动态内容安全呈现，不执行日志指令；报告说明脱敏局限及宿主模型传输风险。
- 验证方式：合成秘密自动扫描、流分片及 Markdown 渲染检查；不使用真实秘密。

### AC-10：双报告一致且不创建报告文件

关联：FR-07、FR-08、BR-10、BR-11、NFR-05。
- Given：同一 run 含通过、失败、未执行和未知样例；使用本身不写文件的合成检查脚本。
- When：执行结束返回结果，随后在同会话取报告；另尝试调用不存在的导出工具或传入报告写盘参数。
- Then：两格式 run ID、任务、状态、退出码和截断一致；返回/取报告不调用报告写盘操作、不创建报告或临时文件；工具列表无导出工具，未声明的写盘参数拒绝。不将已批准脚本或宿主会话自身的存储行为误称为插件报告落盘。
- 验证方式：序列化及两格式字段对照、工具/schema 检查、I/O 调用审计和合成项目文件前后对照。

### AC-11：路径、参数及沙箱边界

关联：FR-01、FR-04、FR-09、BR-01、BR-03、NFR-01、NFR-06。
- Given：中文/空格项目路径、含 shell 元字符的脚本名/参数、自由命令、配置读取的符号链接逃逸和宿主拒绝路径。
- When：请求发现、预览或执行。
- Then：合法输入在目标目录执行且参数不被插件额外解释；非法输入、宿主拒绝和读取边界外路径拒绝；无无约束后备执行、无权限扩大。已批准脚本及其生命周期依 BR-08 和真实宿主限制执行，不声称脚本绝对只读；报告不落盘由 AC-10 单独验证。
- 验证方式：Windows 自动化和宿主受限场景；无法创建链接时登记阻塞，不当作通过。

### AC-12：独立插件的真实宿主闭环

关联：FR-10、NFR-01、NFR-06。
- Given：固定并记录的 DSH/Node/npm 版本、打包插件与合成项目。
- When：按文档安装，执行发现、批准成功任务、拒绝有标记副作用任务、查看报告并卸载。
- Then：宿主可发现/调用；获准任务真实运行；拒绝无副作用；报告可读；卸载后贡献消失；不改 DSH 核心。记录版本、命令和可复核结果，不能只用 import 成功或 mock 代替。
- 验证方式：真实 Windows x64 DSH 验收；若缺运行条件，标受阻，不结项。

### AC-13：并发、重启和禁止行为

关联：FR-05、FR-09、NFR-07、范围边界。
- Given：同项目已有运行；另有已结束 run 与重启环境。
- When：重复发起执行或重启插件。
- Then：重复请求 busy、无第二个执行；重启不重跑；新 run 有新 ID；不混合旧证据。各正常/失败路径均无自动修复、安装、Git 提交/推送/发布或新增外部上传。
- 验证方式：并发/生命周期自动测试、执行调用审计及源码审查；外部网络限制只针对插件新增行为，不掩盖批准脚本或宿主自身网络行为。
