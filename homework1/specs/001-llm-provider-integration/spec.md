# Feature Specification: 接入真实 LLM Provider

**Feature Branch**: `[001-llm-provider-integration]`

**Created**: 2026-07-30

**Status**: Draft

**Input**: User description: "接入真实的LLM Provider，使用当前环境配置的中转站的key，使用中文输出"

## Clarifications

### Session 2026-07-30

- Q: 接入范围应覆盖哪些生成路径？ → A: 只替换当前已有的模拟/占位 LLM 调用点，不扩大到其他功能。
- Q: 中转站配置应采用哪套约定？ → A: 使用通用中转站配置约定：`LLM_API_KEY` 和 `LLM_BASE_URL`。

### Session 2026-07-31

- Q: 中转站接口协议/请求格式应采用哪种兼容协议？ → A: 使用 Anthropic-compatible Messages 协议（`/v1/messages` 风格）。
- Q: Anthropic-compatible Messages 请求的模型名应如何配置？ → A: 新增环境变量 `LLM_MODEL`；未配置时使用项目默认模型 `claude-opus-4-8`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 真实模型生成中文回复 (Priority: P1)

作为使用者，我希望系统在当前已有的模拟或占位 LLM 调用点需要生成内容时调用真实的 LLM Provider，而不是返回模拟内容或固定占位文本，并且默认以中文给出结果。

**Why this priority**: 这是功能的核心价值；只有真实模型参与生成，后续对智能问答、内容生成和作业演示的验证才有意义。

**Independent Test**: 可通过发起一次明确的中文请求独立验证：系统应返回与请求相关、非固定模板化的中文内容，并能证明该内容来自真实模型生成流程。

**Acceptance Scenarios**:

1. **Given** 当前运行环境已配置可用的中转站凭证，**When** 用户提交中文问题，**Then** 系统返回自然、完整、相关的中文回答。
2. **Given** 用户连续提交两个不同问题，**When** 系统处理这些请求，**Then** 每次回复都应针对对应问题生成，而不是复用同一段固定文本。
3. **Given** 用户没有特别要求其他语言，**When** 系统生成回复，**Then** 回复默认使用中文。

---

### User Story 2 - 使用环境中已配置的中转站凭证 (Priority: P2)

作为维护者，我希望系统自动使用当前运行环境中已经配置的中转站访问凭证，而不需要用户在界面或请求内容中手动输入密钥。

**Why this priority**: 这能减少配置摩擦，并避免用户在交互内容中暴露敏感凭证。

**Independent Test**: 可在已配置凭证的环境中启动系统并发起生成请求；用户无需输入密钥即可获得真实模型回复。

**Acceptance Scenarios**:

1. **Given** 当前运行环境存在有效中转站凭证，**When** 用户发起生成请求，**Then** 系统自动使用该凭证完成真实模型调用。
2. **Given** 用户请求内容中不包含任何密钥，**When** 系统处理请求，**Then** 系统仍能在配置正确时完成生成。
3. **Given** 系统展示或记录运行信息，**When** 生成请求被处理，**Then** 中转站凭证不得以明文形式出现在用户可见内容或普通运行记录中。

---

### User Story 3 - 配置异常时给出中文可理解反馈 (Priority: P3)

作为使用者或维护者，我希望当真实 LLM Provider 无法访问、凭证缺失或凭证无效时，系统用中文说明问题，并避免误导性地返回模拟成功结果。

**Why this priority**: 失败场景的反馈决定了问题定位效率，也能防止用户误以为系统已经接入真实模型。

**Independent Test**: 可在缺失或无效凭证环境中发起生成请求；系统应返回清晰的中文错误说明，而不是模拟模型回答。

**Acceptance Scenarios**:

1. **Given** 当前运行环境未配置中转站凭证，**When** 用户发起生成请求，**Then** 系统返回中文提示，说明需要配置有效凭证后才能使用真实模型。
2. **Given** 中转站凭证已配置但不可用，**When** 用户发起生成请求，**Then** 系统返回中文提示，说明真实模型请求失败并建议检查配置或稍后重试。
3. **Given** 真实模型调用失败，**When** 系统生成用户反馈，**Then** 系统不得返回伪装成真实模型生成的占位答案。

---

### Edge Cases

- 当前运行环境中没有配置中转站凭证时，系统应阻止真实生成流程并返回中文可操作提示。
- 中转站凭证存在但已过期、无权限或格式不正确时，系统应提示凭证不可用，且不得泄露凭证内容。
- LLM Provider 暂时不可用、响应超时或达到服务限制时，系统应返回中文失败说明，并保留用户重新尝试的路径。
- 用户要求英文或其他语言输出时，系统应优先遵循用户明确指定的输出语言；未指定时默认中文。
- 模型返回空内容、异常内容或无法完成请求时，系统应以中文说明未能生成有效结果。
- 用户输入为空或只有空白内容时，系统应提示用户提供明确请求，而不是调用模型生成无意义回复。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 将当前已有的模拟或占位 LLM 调用点替换为真实 LLM Provider 生成回复，不得以固定占位文本、模拟结果或硬编码内容替代这些调用点的真实生成。
- **FR-002**: 系统 MUST 使用当前运行环境中按通用中转站配置约定提供的访问凭证和访问地址完成 LLM Provider 接入；配置项为 `LLM_API_KEY` 和 `LLM_BASE_URL`，请求协议采用 Anthropic-compatible Messages 协议（`/v1/messages` 风格），用户不需要在每次请求中提供密钥。
- **FR-003**: 系统 MUST 在未指定其他语言时默认以中文输出面向用户的回答、状态信息和错误提示。
- **FR-004**: 系统 MUST 在用户明确要求其他输出语言时尊重该语言要求，除非该要求与安全或系统约束冲突。
- **FR-005**: 系统 MUST 在缺少、无效或不可用的中转站凭证场景下返回清晰中文错误反馈，并说明用户或维护者下一步应检查配置。
- **FR-006**: 系统 MUST 避免在用户界面、普通运行记录、错误信息或生成内容中泄露中转站凭证的完整值。
- **FR-007**: 系统 MUST 能区分真实模型生成成功与模型调用失败；失败时不得返回伪装成成功生成的模拟答案。
- **FR-008**: 系统 MUST 对空输入或无效输入给出中文校验提示，避免发起无意义的生成请求。
- **FR-009**: 系统 MUST 为每次生成请求提供可验证的结果状态，使测试者能够判断请求是成功生成、配置失败、服务失败还是输入无效。
- **FR-010**: 系统 SHOULD 在模型服务临时不可用或响应超时时给出中文重试建议，并确保用户不会看到未完成或误导性的半成品结果。
- **FR-011**: 系统 MUST 支持通过环境变量 `LLM_MODEL` 指定 Anthropic-compatible Messages 请求使用的模型名；当 `LLM_MODEL` 未配置时，系统 MUST 使用项目默认模型 `claude-opus-4-8`。

### Key Entities *(include if feature involves data)*

- **LLM 请求**: 用户提交的待生成任务，包含用户输入、期望输出语言、请求状态和生成结果。
- **Provider 配置**: 当前运行环境中按通用中转站配置约定提供的配置集合，包含 `LLM_API_KEY` 的可用性状态、`LLM_BASE_URL` 的访问目标、可选 `LLM_MODEL` 模型名、Anthropic-compatible Messages 协议约束和安全约束；不包含可公开展示的密钥明文。
- **生成结果**: 返回给用户的中文或用户指定语言内容，包含成功结果或可理解的失败说明。
- **调用状态**: 对一次生成过程的业务状态描述，例如成功、输入无效、凭证缺失、凭证不可用、服务不可用或超时。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在凭证配置正确且服务可用的环境中，95% 的普通中文生成请求能在 10 秒内返回相关中文回复。
- **SC-002**: 在默认语言场景下，100% 面向用户的成功回复和失败提示均使用中文。
- **SC-003**: 在缺失或无效凭证场景下，100% 的请求返回中文配置错误说明，且不会返回模拟成功内容。
- **SC-004**: 在测试样本中，0 个用户可见输出或普通运行记录包含完整中转站凭证明文。
- **SC-005**: 至少 90% 的测试用户能够根据失败提示判断下一步应检查凭证配置、稍后重试或补充输入。
- **SC-006**: 对同一批不同输入进行测试时，95% 的回复能体现输入差异并与对应问题相关，证明系统未使用固定占位响应。

## Assumptions

- 当前运行环境会在部署或启动前通过 `LLM_API_KEY` 和 `LLM_BASE_URL` 提供访问真实 LLM Provider 所需的中转站配置和凭证；中转站接口按 Anthropic-compatible Messages 协议（`/v1/messages` 风格）调用；模型名可通过 `LLM_MODEL` 配置，未配置时使用项目默认模型 `claude-opus-4-8`。
- 本功能范围聚焦于“替换当前已有模拟或占位 LLM 调用点、使用已有环境配置调用真实模型并中文输出”，不包含新增密钥管理界面、计费管理、多供应商后台切换界面或新增其他生成入口。
- 默认输出语言为中文；当用户明确要求其他语言时，系统可按用户要求输出。
- 凭证属于敏感信息，系统只使用它完成授权访问，不向用户展示完整值。
- 真实 LLM Provider 的服务稳定性、配额和可访问性可能受外部服务状态影响；系统需要清晰反馈这些失败，但不负责保证外部服务永远可用。
